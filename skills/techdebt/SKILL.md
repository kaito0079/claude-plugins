# 技術的負債の検出と報告

コードベースをスキャンして技術的負債を特定し、改善提案をまとめたレポートを生成

## このスキルを使用するタイミング

- セッション終了時の品質チェック
- PR 作成前のコード品質確認
- 定期的な技術的負債の棚卸し
- リファクタリング対象の特定

## Instructions

以下の手順で技術的負債を検出し、レポートを生成：

### 1. スキャン対象の確認

まず、現在のセッションで変更されたファイルを確認：

```bash
git diff --name-only HEAD~5
git diff --name-only --cached
```

変更がない場合は、ユーザーに対象ディレクトリを確認する。

### 2. 重複コードの検出

変更されたファイルと同じモジュール内で、類似パターンを検索：

- 同じロジックの繰り返し（3回以上）
- コピーペーストが疑われるコードブロック
- 共通化可能なバリデーションやデータ変換処理

### 3. コードスメルの特定

以下の観点でコードを分析：

**バックエンド:**
- 100行を超えるメソッド
- 4階層以上のネスト
- 5つ以上のパラメータを持つメソッド
- God Object（責務が多すぎるクラス）
- N+1 クエリの可能性
- 不適切な例外処理（空の catch ブロック等）

**フロントエンド:**
- 200行を超えるコンポーネント
- props の数が多すぎるコンポーネント（7個以上）
- useEffect の依存配列の不備
- 不要な再レンダリングの可能性
- any 型の使用

### 4. 未使用コードの検出

- 未使用の import 文
- 未使用の変数・関数
- デッドコード（到達不可能なコードブロック）
- TODO/FIXME コメントの集計

### 5. セキュリティ関連の確認

- ハードコードされた認証情報やシークレット
- SQL インジェクションの可能性
- XSS の可能性
- 不適切な権限チェック

### 6. レポートの生成

分析結果を以下の形式で出力：

```
## 技術的負債レポート
日付: YYYY-MM-DD
対象: [スキャン対象のファイル/ディレクトリ]

### 高優先度（即座に対応推奨）
- [セキュリティリスクや重大なバグの可能性]

### 中優先度（次のスプリントで対応）
- [コードスメル、設計上の問題]

### 低優先度（リファクタリング時に対応）
- [スタイルの改善、軽微な重複]

### 統計
- スキャンファイル数: X
- TODO/FIXME数: X
- 重複コードブロック数: X
- 複雑度の高い関数数: X

### 改善提案
1. [具体的な改善提案と対象ファイル]
```

## 重要な注意事項

- スキャンは読み取り専用で行い、ファイルを変更しない
- レポートは標準出力に表示（ファイルに保存する場合はユーザーに確認）
- 大規模なスキャンは時間がかかるため、対象を絞ることを推奨
