# Team Builder

設計書やタスクリストに基づいてエージェントチームを構築し、並列実装とコードレビューを行うClaude Skillです。
技術ドメインで作業を分割し、依存関係を管理しながら効率的に開発を進めます。

## 何ができるか

- 設計書・タスクリストからエージェントチームを自動構築
- 技術ドメイン（バックエンド / フロントエンド / インフラ等）でタスクを分割
- 独立タスクの並列実行で実装を高速化
- 実装完了後に自動でコードレビューを実施
- レビュー指摘をリーダーが一括修正

## こんな時に使える

- 設計書に基づいて複数ファイルを一気に実装したい時
- バックエンド + フロントエンド + インフラなど複数ドメインにまたがる開発
- 3つ以上の独立タスクを並列で効率化したい時
- セキュリティ / パフォーマンス / テストカバレッジ等の観点別レビューをしたい時

## 使わない方がいいケース

- タスクが1〜2個で並列化の効果が薄い場合
- 単一ドメインの小規模な変更
- 順次依存が多く直列化せざるを得ない作業
- 同一ファイルを複数エージェントが編集する必要がある場合（上書きによるデータ消失リスク）
- コスト感度が高い場合（単一セッションの数倍のトークンを消費）

## 使い方

### 1. スキルを呼び出す

```
/team-builder
```

設計書やタスクの内容を伝えると、チーム構成を提案します。

### 2. 実行の流れ

```
タスク分析・分割
  ↓
チーム構成決定（リーダー + 実装担当 × N + レビュワー）
  ↓
タスク登録・依存関係設定
  ↓
実装エージェント並列起動
  ↓
進捗管理 → 全実装完了
  ↓
レビュワー起動 → 指摘をリーダーが修正
  ↓
クリーンアップ
```

### 3. モデル戦略の選択

コストと品質のバランスに応じて4つの戦略から選択できます。

| 戦略 | リーダー | 実装担当 | レビュワー | 用途 |
|------|---------|---------|-----------|------|
| **adaptive**（推奨） | opus | sonnet | opus | 通常の開発 |
| **deep** | opus | opus | opus | 複雑な設計、セキュリティ重要 |
| **fast** | sonnet | sonnet | sonnet | 速度重視、定型作業 |
| **budget** | sonnet | haiku | sonnet | コスト最小化 |

## チーム構成パターン

### パターン1: フルスタック機能

```
backend-dev (sonnet)  → APIコントローラー、モデル、マイグレーション
frontend-dev (sonnet) → ページ、コンポーネント、APIフック
infra-dev (sonnet)    → IaC定義、IAMポリシー、環境設定
reviewer (opus)       → 全体レビュー
```

### パターン2: API + データベース

```
schema-dev (sonnet)   → マイグレーション、モデル定義、シードデータ
api-dev (sonnet)      → コントローラー、ユースケース、スキーマ
test-dev (sonnet)     → 統合テスト、ユニットテスト
reviewer (opus)       → 全体レビュー
```

### パターン3: リファクタリング

```
refactor-a (sonnet) → サービスA側のファイル群
refactor-b (sonnet) → サービスB側のファイル群
reviewer (sonnet)   → 全体レビュー
```

### パターン4: 並列レビュー・調査

```
security-reviewer (opus)    → セキュリティ観点
performance-reviewer (opus) → パフォーマンス観点
test-reviewer (opus)        → テストカバレッジ観点
```

## 重要なルール

| ルール | 理由 |
|--------|------|
| 同一ファイルの並行編集禁止 | 後から書き込んだ方が先の変更を無言で上書きする |
| エージェント数は3〜4が最適 | 多すぎると調整コスト増、少なすぎると並列効果薄 |
| レビューは全実装完了後 | 途中レビューは手戻りが増えるだけ |
| レビュー修正はリーダーが担当 | エージェント再起動のオーバーヘッドを避ける |
| プロンプトに全情報を含める | エージェントは独立セッションで動く |

## ファイル構成

```
team-builder/
├── SKILL.md     # Claude向け指示書（英語）
└── README.md    # このファイル（日本語解説）
```

## 前提条件

- Claude Code のチーム機能（TeamCreate, Task tools, SendMessage）が利用可能であること
- 並列化の効果がある程度の規模のタスクであること（3タスク以上推奨）
