# 状況確認

作業を再開するとき、または別のセッションで同じリポジトリを触った後に、現在地を整理する。

⬛ MUST
- このスキルではファイルの編集・コミット・push・ブランチの切り替えを行わない。読み取りと `git fetch` だけにする。
- 推測で状況を補わない。コマンドの出力で確認できたことだけを報告する。

## 手順

### 1. 状態を集める

次のコマンドを、**1 つずつ別々の Bash 呼び出し**で実行する。

```
git branch --show-current
git status --short
git fetch --quiet
git log --oneline @{upstream}..HEAD
git log --oneline HEAD..@{upstream}
git stash list
git worktree list
gh pr view --json number,title,state,isDraft,reviewDecision,url
gh pr checks
```

⬛ MUST
- 1 回の呼び出しには git / gh のコマンドを 1 つだけ書く。`;` `&&` `|` でほかのコマンドとつながない。
  `echo` での見出し、`2>/dev/null` などのリダイレクト、`||`、`$( )` も使わない。
  サンドボックスで git / gh だけを外で動かす設定では、複合コマンドにするとサンドボックスの中で実行され、
  `~/.gitconfig` などが読めずに失敗するため。単独の呼び出しにしておけば、許可リストの `Bash(git *)` にも当てはまる。
- コマンドが失敗したときは、エラーの内容を読んで次のように扱う。
  - upstream がない (`no upstream configured` など): 未 push と遅れの項目は「upstream なし」として扱う
  - PR がない、または `gh` が使えない: PR と CI の項目を省く
  - それ以外 (権限やサンドボックスで読めないなど): 取れなかった項目と、エラーの 1 行目をそのまま報告する。推測で補わない

### 2. 意図しないコミットを確認する

⬛ MUST
- 未 push のコミットそれぞれを `git show --stat --format='%h %s' <sha>` で確認し、このセッションの作業と関係があるかを判断する。
- 関係のないコミットを見つけても、取り消し・移動・リベースはしない。報告だけにする。

◆ SHOULD
- このセッションでステージしたはずの変更が、ステージから外れていないかも確認する。

### 3. 報告する

次の 4 つの見出しで、それぞれ 3 行以内にまとめる。

| 見出し | 内容 |
|--------|------|
| 現在地 | ブランチ、未コミットの変更、未 push のコミット (件数と、他の作業のものが混ざっているか)、PR と CI の状態 |
| このセッションで決めたこと | 会話の中で合意済みの方針。なければ省く |
| 未決事項 | ユーザーの判断を待っている点を番号付きリストで挙げる |
| 次の一手 | 1 つだけ提案する |

◆ SHOULD
- 未 push のコミットが多い、upstream より遅れている、CI が失敗している、のいずれかに当てはまる場合は、現在地の最初の行で触れる。
