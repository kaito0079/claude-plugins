# Dig Thinking

自分の考えや判断基準を、Claude に質問してもらいながら言語化する Claude Skill です。
自分がいない場面でも、メンバーやエージェントが同じ判断にたどり着けるように、判断メモとしてまとめます。

## 使い方

```
/dig-thinking
/dig-thinking コミット署名をやめた判断
```

引数に、深掘りしたい判断や出来事を書きます。省略すると、Claude が「最近迷った判断」を聞くところから始めます。
自動では起動しません。深掘りしたいときに、自分で呼び出してください。

## 流れ

1. 深掘りする出来事を 1 つ決めます。抽象的なテーマしかない場合は、具体的な出来事を挙げてもらいます。
2. Claude が 1 回に 1〜3 問ずつ、仮説を添えて質問します。仮説を直す形で答えられます。
3. 具体化、なぜの掘り下げ、反例、優先順位、他者視点、汎用化の角度から掘ります。
4. 回答どうしや、既存のルールとの食い違いがあれば、その場で指摘されます。
5. 原則・理由・適用範囲・例外と境界・優先順位・具体例・未解決の問いをまとめた判断メモが提示されます。
6. 内容を確認して承認すると、指定した場所か、作業ディレクトリの判断基準ファイル（`PRINCIPLES.md` など）に保存できます。

## grill-me との違い

Matt Pocock 氏の [grill-me](https://github.com/mattpocock/skills)（MIT License）の、ラウンド制で推奨案を添えて質問する進め方を参考にしています。

| | grill-me | dig-thinking |
| --- | --- | --- |
| 深掘りする対象 | 計画や設計（何を作るか） | 判断している本人の考え（なぜそう判断するか） |
| 終わる条件 | 設計の分岐がすべて決まった | 原則・理由・例外・優先順位がそろい、本人が承認した |
| 成果物 | 共通理解（grill-with-docs では用語集と ADR） | 判断メモ |

設計を詰めたいときは grill-me、自分の判断基準を言語化したいときはこのスキル、という使い分けを想定しています。

## 注意

- 公開リポジトリに保存する場合は、社名、顧客名、案件名などの固有の情報を取り除いてから書き込みます。
- 判断の良し悪しを Claude が評価することはありません。あくまで本人の考えを言葉にするためのスキルです。
