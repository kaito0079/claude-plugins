# grill-me

計画・設計・方針について Claude に質問を重ねさせ、決めるべきことを決め切るためのスキル。

## 使い方

```
/kaito-workflow:grill-me
/kaito-workflow:grill-me 通知機能の再設計
```

`grill-me` という名前のスキルは広く配布されていて、プロジェクトに置かれていることも多い。プロジェクトに同じ名前のスキルがあると、短い名前の `/grill-me` ではそちらが動くので、名前空間付きで呼ぶ。

テーマを省くと、直前までの会話で扱っている計画を対象にする。Claude が自動で使うことはなく、呼んだときだけ動く。plan mode はオフにしておく (計画を急いで書こうとして、質問が浅くなるため)。

## 進め方

1. 規模を確かめる。テーマが大きすぎる場合は、先に分割を提案される
2. Claude が調べた前提を、根拠 (`file:line` など) 付きの一覧で示す。違っていれば番号で訂正する
3. 1 問ずつ聞かれる。前提が決まっている質問のうち、後に続く決定を最も多く抱えるものから順に聞かれる
4. 決定ツリーを掘り切ったら、目的・スコープ外・制約・失敗時・運用・移行・関係者の観点で、まだ触れていないものを 1 問ずつ確認する
5. 最後に premortem (「半年後に失敗していたら原因は？」) と「ほかに詰めたい点は？」を聞かれる
6. 決定事項・却下した選択肢・変更した決定・未決事項・次の一手がチャットに要約される

## 質問の形と答え方

各質問には通し番号が付き、2〜4 個の選択肢と、それぞれのメリット・デメリットが付く。Claude の推奨回答は付かないので、どれを選ぶかは自分で決める。

「A」のように選択肢の記号で答えられる。ほかの案、「分からない」「保留」も正式な回答として扱われ、未決事項に回る。前の回答と矛盾したときは、どちらを採るかを改めて聞かれる。見た目や触り心地のように、話し合っても決まらない問いは「要プロトタイプ」として未決事項に回る。

テンポよく進めたいときは「まとめて聞いて」と伝えると、互いに依存しない質問を最大 3 問まで同時に聞かれる。その場合は「Q1 A、Q2 B、Q3 保留」のように番号で答える。

## しないこと

ファイルの編集・コミット・push はしない。要約もファイルには書き出さず、チャットに出す。要約の後も、作業を明示的に頼むまで実装には入らない。
