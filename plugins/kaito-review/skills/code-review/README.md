# code-review

変更差分に対して、観点別のサブエージェントを並列に起動してコードレビューを行う Claude Skill です。

## できること

- PR 番号を指定するとその PR を、指定しないと現在のブランチの PR をレビューします。PR がなければ、デフォルトブランチとのローカル差分をレビューします。
- 常時 4 つの観点（ロジック / セキュリティ / テスト / 改善提案）でレビューします。
- リポジトリに規約文書（`CLAUDE.md`、`.claude/rules/`、`CONTRIBUTING.md` など）があれば、規約準拠の観点を追加します。
- 各観点が拾った「他観点での気づき」は、担当の観点を追加で起動して検証してから統合します。
- PR に未解決のレビュースレッドがあれば、指摘への対応が適切かを判定します。判定は「未対応」「対応が不十分」「説明の再確認が必要」「対応済み（解決してよさそう）」の 4 つです。既存スレッドと同じ内容の指摘は、新規には出しません。
- 結果を `[MUST]` / `[IMO]` / `[ASK]` / `[NITS]` / `[LGTM]` のタグ付きで表示します。

PR へのコメント投稿やスレッドの解決は行いません。レビュー結果の表示までを担当します。

## 使い方

```
/code-review           # 現在のブランチの PR（なければローカル差分）をレビュー
/code-review 123       # PR #123 をレビュー
レビューして             # 自然言語でも起動できます
指摘への対応を確認して     # 再レビューのときに
```

## 特徴

- **エージェント定義が不要です。** 観点ごとのルールを `references/` に置き、`general-purpose` サブエージェントにプロンプトとして渡します。スキルのディレクトリだけで完結します。
- **プロジェクトに合わせて動きます。** 汎用のルールだけでは拾えない規約は、プロジェクトの規約文書から読みます。規約文書に書かれていない事項は、規約違反として指摘しません。
- **読む範囲と指摘する範囲を分けています。** 判断のために、変更ファイルの全体や呼び出し元などの関連コードも読みます。指摘の対象は、今回の変更と、変更によって影響を受ける箇所に限ります。
- **慣例を尊重します。** 既存のパターンに沿った書き方は指摘しません。テストのない領域では、テストの追加も求めません。

## ファイル構成

```
code-review/
├── SKILL.md                               Claude 向けの指示書
├── README.md                              このファイル
└── references/
    ├── review-criteria.md                 全観点共通の基準・タグ・出力フォーマット
    ├── perspective-logic.md               ロジック観点のルール
    ├── perspective-security.md            セキュリティ観点のルール
    ├── perspective-test.md                テスト観点のルール
    ├── perspective-suggestion.md          改善提案観点のルール
    ├── perspective-conventions.md         規約準拠観点のルール（規約文書がある場合のみ）
    └── existing-comments.md               既存コメントの対応状況の判定ルール（PR モードのみ）
```
